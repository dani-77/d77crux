# AGENTS.md — d77crux

d77crux is Daniel Azevedo's collection of CRUX 3.8 ports, distributed with
httpup, plus `binpkg/`: verified CRUX binaries that prt-get installs instead
of compiling. Everything written in this repository (code, comments, docs,
commit messages) is in English.

## Ports

- Ports are signed by Daniel on his CRUX machine (`.signature`, checked
  against `/etc/ports/d77crux.pub`); `.footprint` and `.md5sum` come from
  `pkgmk` there too. Agents never sign ports and never commit or push a
  `.signature` that no longer matches its Pkgfile. Edit and commit Pkgfiles
  locally and leave signing to Daniel.
- `REPO` (the httpup index) is regenerated by Daniel with httpup-repgen
  after signing. A port reaches installed systems only then.
- `.httpup-repgen-ignore` lists what httpup must not distribute. It excludes
  `\.pub` and `\.sec` everywhere, and `^binpkg` and `AGENTS.md`. A port's
  source file must not match any of these patterns: that is why the
  `d77crux-cache` port ships its public key as `pubkey.signify`.

## binpkg: binary cache for prt-get

Read `binpkg/README.md` first. The design, in short:

- prt-get stays the only package authority. `d77crux-cache` only places
  verified archives in **official** port directories (core/opt/xorg), where
  pkgmk's own up-to-date check makes prt-get install them. It never runs
  pkgadd, keeps no package state of its own, and never touches other
  collections. If it does nothing, prt-get compiles, as on any CRUX system.
  Keep it that way: a second planner, installer or ownership registry next
  to prt-get was tried and dropped as unstable.
- An archive is placed only if the ports tree has exactly its
  version-release, the port's Pkgfile verifies against the collection's
  `.signature`, and its SHA-256 matches the signed manifest. The tool
  refuses to run unless pkgmk builds xz (`PKGMK_COMPRESSION_MODE="xz"`), and
  unless CFLAGS are CRUX's default or the user opted in with
  `ACCEPT_GENERIC=yes` in `/etc/d77crux-cache.conf`. The tool adapts to the
  user's pkgmk.conf; never ask users to change it for the tool beyond xz. Archives go to the port directory, or to
  `PKGMK_PACKAGE_DIR` when it is one fixed directory. A value that depends on
  the port directory is refused. In a shared directory, an archive the tool
  did not place is never overwritten or removed.
- Archives come byte for byte from Jaeger's updated ISO (crux.ninja). Its
  SHA-256 is the identity of an import. Imported files are never rebuilt or
  modified.
- `.github/workflows/import-crux-iso.yml` imports, signs and publishes
  automatically (daily). Releases are created with `--latest=false`: the
  d77crux-kernel release must stay "Latest", and sysv-d77's
  `fetch-kernel.sh` looks kernel releases up by tag prefix.
- Signing: the signify key exists only as secrets of the `binpkg-release`
  environment, which is restricted to `main`. There is no other copy. If it
  is lost or exposed, rotate it: new key, new secrets, new
  `d77crux-cache/pubkey.signify`, port bump. Nothing unsigned is ever
  published, and clients refuse a channel pointer older than the last one
  they accepted.

Before changing binpkg, run:

    bash binpkg/tests/test-d77crux-cache.sh
    shellcheck -S warning d77crux-cache/d77crux-cache

Changes to what reaches installed systems are tested in a VM first, with
sysv-d77's harness (`~/Remaster/sysv-d77`: `scripts/install-vm-mocinha.sh`,
`tests/vm-update-trial.py` with `tests/vm-sysup-guest.sh`), against an
install made by the sysvd77 ISO's own Mocinha.
